# Запуск, хранение и публикация

## Локально

Node.js 22.17+, `npm ci`, `npm run dev`. Проверки: `npm test`, `npm run typecheck`, `npm run build`. SQLite хранится в `.data/leads.sqlite`, не входит в Git и сохраняется между перезапусками. Это локальное хранилище; на Netlify оно не используется.

## Netlify

Связанный проект: `kvarta-roastery-ilya`, ID `994c66c2-4d28-4db9-8e5e-53ebebbbb580`. Новый checkout связывается командой `netlify link`. Публикация: `npx netlify-cli deploy --prod --context production`. На Windows перед упаковкой остановить локальный Next.js: плагин временно переименовывает `.next`, и открытый сервер может блокировать каталог. Статический export не подходит: серверной форме нужна функция.

Переменные окружения на Netlify: `LEAD_STORAGE=netlify`, `LEAD_HASH_SECRET` — случайная строка из 32+ байт. Пример без настоящих значений — `.env.example`. Секреты не имеют префикса `NEXT_PUBLIC_`, не коммитятся и не передаются браузеру. Смена HMAC-секрета меняет ключи телефонов, поэтому без миграции сбросит возможность находить старые дубли; не менять его без необходимости.

Основной `POST /api/lead` на хостинге обслуживает `netlify/functions/lead.ts`, при локальном `next dev` — Route Handler. Оба вызывают один `handleLead`. Вынесение штатной Netlify Function потребовалось после проверки опубликованной версии: путь к хранилищу в Next runtime зависал. Ошибка не маскируется успешным ответом.

## Данные заявок

Site-wide Netlify Blobs `kvarta-leads-v1`, доступ через сервер и панель владельца Netlify. Один JSON-документ на HMAC нормализованного телефона содержит историю заявок. Внутри — ID, время UTC, имя, телефон E.164, интерес, комментарий и рекламные параметры. Чтение strong; первая запись `onlyIfNew`, обновление `onlyIfMatch` по ETag. Заявка и отметка дедупликации сохраняются одним атомарным действием; отдельной блокировки без заявки нет. Конфликт вызывает повторное чтение, ошибка хранилища — 503.

Десятиминутное окно отсчитывается от последней **созданной** заявки; дубли его не продлевают. Ровно через 10 минут разрешается новая запись. Ключи не содержат открытый телефон; реальные данные остаются в JSON, доступном владельцу. Публичного API чтения заявок нет. Панель: Netlify → проект → Blobs → `kvarta-leads-v1`. Проверочные записи имеют имя с `QA`.

## Атрибуция

Первый переход в пределах вкладки: `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `utm_id`, `yclid`, `fbclid`, `landing_url`, `referrer`. Сохраняется до гидратации и повторно используется при отправке. `submit_url` — адрес отправки. Смена выбора продукта не теряет первый рекламный переход. Нужная реклама идентифицируется только если рекламная ссылка размечена; сайт не может восстановить отсутствующий ID объявления.

## Границы

Это небольшая мастерская и тестовое задание, не CRM. При росте нагрузки или требований к поиску — Postgres. Honeypot, пределы полей/тела, Origin и дедупликация реализованы; полноценный массовый антиспам и SMS-подтверждение не входят в ТЗ. Тариф аккаунта Legacy Free сохранён. Telegram не настроен: бот и получатель не предоставлены, пункт необязательный.
