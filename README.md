# Кварта — обжарка кофе в Минске

[Сайт](https://kvarta-roastery-ilya.netlify.app) · [Репозиторий](https://github.com/ilyaseverin/kvarta-roastery)

Учебный лендинг вымышленной мастерской. Next.js 16, React 19, TypeScript, Netlify. Направление «Ритм недели»: обжарка в четверг, доставка в пятницу. Авторские CSS-упаковки, локальный шрифт, оптимизированные фотографии, адаптивная вёрстка и reduced motion.

**Заявки.** Собственный `POST /api/lead`: серверная проверка белорусского номера (включая стационарные), нормализация в E.164, сохранение рекламных параметров, понятные ошибки. В production — site-wide Netlify Blobs: один JSON-документ на HMAC телефона, история заявок и время последней записи сохраняются одним атомарным conditional write (`onlyIfNew` / `onlyIfMatch`), чтение — strong consistency. Это исключает дубль даже при параллельных запросах. Через 10 минут разрешается новая заявка; дубли не продлевают окно. Хранилище выбрано под существующий бесплатный Legacy-тариф: Netlify Database потребовал бы смены тарифа. Локально — постоянный SQLite в `.data/`, compare-and-swap по ревизии. Публичного чтения заявок нет. Просмотр: Netlify → проект → Blobs → `kvarta-leads-v1`.

**Атрибуция и допущения.** Первый переход в пределах вкладки сохраняется в sessionStorage: UTM, `yclid`, `fbclid`, landing URL, referrer; при отправке добавляется submit URL. Для определения объявления в рекламной ссылке нужен `utm_content` или `utm_id`. Имя, телефон и интерес обязательны, комментарий необязателен. В ТЗ нет телефона мастерской, цены доставки до 50 BYN и состава подписки: контакты — адрес/часы/обратный звонок, неизвестные условия уточняются менеджером. Подписка — 2 × 250 г за 54 BYN **в месяц**, не в неделю. Изображения процесса иллюстративные; авторы и лицензии в [docs/assets.md](docs/assets.md).

**Человек и ИИ.** Пользователь задал задачу, потребовал нешаблонный дизайн, выбрал комбинацию первой схемы и фотоконцепции, поправил направление первой реализации. ИИ разобрал MHTML, предложил схемы и архитектуру, написал код и тесты, провёл проверки. ИИ сначала слишком сместил акцент с календаря на фотографию — пользователь заметил; возвращены крупные листки «Чт / Пт». Предложение встроенного Postgres не учло Legacy-тариф — проверка реального аккаунта выявила ограничение, выбрано Blobs. При сборке обнаружено, что ETag SDK может отсутствовать: добавлена явная проверка вместо небезопасной записи. Журнал: [docs/ai-worklog.md](docs/ai-worklog.md).

**Проверки и границы.** `npm test` проверяет валидацию, атрибуцию, 30 параллельных отправок, границу 10 минут, ошибки хранилища и SQLite между соединениями. Дополнительно проверяются опубликованный API, мобильная вёрстка и Lighthouse. Telegram — необязательный пункт ТЗ, не подключён; полноценная CRM и массовый антиспам вне объёма. При росте числа заявок перенёс бы хранилище в Postgres и добавил рабочие контакты клиента. Итоги проверок — [docs/verification.md](docs/verification.md).

## Локальный запуск

Нужен Node.js 22.17+.

```sh
npm ci
npm run dev
npm test
npm run typecheck
npm run build
```

## Netlify

Проект связан через `.netlify/state.json` локально; этот файл не публикуется в Git. Для другого аккаунта — `netlify link`. В переменных Netlify задать `LEAD_STORAGE=netlify` и случайный `LEAD_HASH_SECRET` (32+ байта). Пример без секретов: `.env.example`. Развертывание: `npx netlify-cli deploy --prod --context production`. Не использовать статический export: обработчику формы нужна функция. Секреты остаются в окружении сервера и не имеют префикса `NEXT_PUBLIC_`.
